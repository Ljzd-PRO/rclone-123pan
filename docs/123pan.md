# 123Pan 后端

remote 类型为 `123pan`，命令行 flag 使用 `--pan123-` 前缀。当前范围仅包括个人账号的用户名/密码认证。

## 配置

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| `user` | 必填 | 个人账号手机号或邮箱；敏感信息。 |
| `pass` | 必填 | 经 rclone obscure 处理的密码；敏感信息。 |
| `access_token` | 内部字段 | 缓存的 token；隐藏且敏感。 |
| `root_folder_id` | `0` | 数字账号根目录；高级且敏感。 |
| `platform` | `web` | 请求头值；签名始终固定使用 `web/3`。 |
| `upload_concurrency` | `3` | 单文件数据上传并发数，范围 1 至 10。 |
| `hash_memory_limit` | `10Mi` | MD5 计算和输入重放的内存阈值。 |
| `api_min_interval` | `700ms` | 每个控制端点的最小请求间隔，突发容量为 1。 |
| `verify_timeout` | `60s` | 写操作最终状态的确认期限。 |
| `encoding` | 平台安全默认值 | Display/Windows/反斜杠/边缘空格/结尾句点/无效 UTF-8 编码。 |

认证只支持手机号和邮箱两类账号的密码登录，不会自动处理短信、微信、验证码或交互式风控。如果 API 拒绝登录，请先在 123 网盘官方网站完成所需操作，再重新尝试。缓存 token 收到 401 后只刷新一次，并通过可安全支持 64 路并发的 singleflight 协调；第二次 401 会直接返回，不会循环登录。

本后端必须直连 123 网盘，不使用 OpenList 的公共 token 服务；该服务属于另一个 `123_open` driver。

## 列表与元数据

读取实现声明支持快速 MD5，保留服务端更新时间用于展示；由于 Web API 无法设置修改时间，因此 `Precision()` 返回 `fs.ModTimeNotSupported`。对象同时公开 ID 和 ParentID，供 `lsjson`、RC 诊断和破坏性操作复核使用。

每个目录按每页 100 项、`file_id desc` 排序读取。只有 `Total`、唯一 ID、名称和终止标志全部一致时才返回结果。一轮一致性检查失败后，会丢弃整轮结果并最多重试三次。

解码后名称发生碰撞，或两个不同 ID 具有相同可见名称时，都会以路径歧义错误失败关闭，不会任意选择对象。自定义根目录通过由 ID 支撑的目录遍历解析；初始化成功前，解析出的根目录必须能够完整列出。

## 下载

下载时先请求最新的完整元数据，严格解开可选 Base64 参数，在禁用自动跳转的情况下解析 302 或 JSON redirect，并使用单独、未认证的数据面客户端。

Range、Seek 和后缀范围请求都由 rclone 规范化；后端会验证返回状态、`Content-Range`、声明长度和实际数据流长度。最终 CDN URL 返回 403 时，只刷新一次签名 URL；正文一旦已经读取部分内容，绝不会在内部静默续传。

## MD5、秒传与上传

> [!WARNING]
> 2026-08-15 已通过官方 Web 脱敏抓线确认当前单片、多片和秒传线型。修复后的后端已完成 0/1/16 MiB−1/16 MiB/16 MiB+1/48 MiB+1 上传、100/101 项分页、完整下载、秒传、可恢复 Update、Move/DirMove、精确软删除、Rmdir、core Copy/sync、bisync、四种 VFS cache mode、HTTP/DLNA/WebDAV/FTP/SFTP/S3/NFS serve、macOS nfsmount 与 crypt 包装的隔离真实闭环；其他平台原生挂载和七日 canary 仍待逐级验证。详见[真实账号测试记录](live-testing.md)。

上传时首先向输入源请求 MD5。输入源提供有效 MD5 且大小已知时，可以在不读取正文的情况下请求秒传。否则只读取输入一次：不大于 `hash_memory_limit`（默认 10 MiB）的数据保存在内存中，更大或大小未知的数据安全地写入 `--temp-dir`，随后 rewind 并恢复 accounting 包装。声明大小、实际大小与 MD5 必须一致。

`Reuse=true` 仍然只是候选成功。当前官方 Web 的同 MD5 异名秒传会返回 `FileId=0`，随后在列表中出现新的正 ID；后端只接受父目录中唯一的名称、大小和 MD5 精确匹配。非零 FileID 还必须与响应 ID 一致。命中时正文读取字节数和数据面 PUT 都为零，0 ID 永远不会用于破坏性操作或数据上传。

秒传未命中时，从两种经过明确校验的模式中选择：三个临时凭据全部存在时，使用 AWS SDK v2 访问服务端提供的 path-style endpoint；三个凭据全部为空时，使用 123 网盘预签名 URL。凭据只出现一部分属于畸形响应，必须拒绝。

预签名上传严格采用 `upload_request` 返回的 `SliceSize`。隔离实测已观察到 16 MiB 与 32 MiB 两档；当前 profile 只接受这两个值，其他值失败关闭。每批最多申请十个 URL，默认三个并发上传任务。每个上传任务在最多三次尝试中保留完全相同的分片字节；并发 403 通过 singleflight 协调一次批次 URL 刷新。生产者采用反压，因此 payload 内存上界随并发数和服务端分片档位增长，默认最坏约为 `3 × 32 MiB` 加固定开销，而不是随文件大小增长。零字节文件仍会发出一次明确的零长度 PUT。

完成请求不会在响应不明确时盲目重试。后端会改为查找精确文件 ID，并核验名称、父目录、大小和 MD5；如果无法证明最终状态，会在错误中报告 upload/file ID。`Reuse=true`、数据 PUT 200 和完成接口 `code=0` 都不能单独作为上传完成证据。

## 可恢复的对象替换

替换已有文件时按目标路径串行化，绝不原地覆盖旧对象。后端会上传并验证一个带 128 位随机值的 staging 名称，把旧 ID 改为同样唯一的 backup 名称，提升 staging ID，验证最终对象，然后只把已经记录的 backup ID 移入回收站。

响应丢失时，通过观察精确 ID 的当前名称来协调状态。失败会触发反向操作；回滚不完整时，错误只包含人工恢复所需的精确 staging ID 和 backup ID。

如果 backup 清理结果不明确，且已无法证明旧 backup ID 仍存在，回滚会有意让经过验证的新文件保留在目标名称，绝不会仅为了让清理看似成功而移动或回收该新文件。

## 删除和目录操作

删除始终表示把一个刚刚重新验证的 ID 移入回收站。`Rmdir` 拒绝逻辑 root 和 ID 0，要求连续两次完整列表均为空，然后再次核验目录 ID、父目录和名称。`Mkdir` 响应丢失后，只有恰好一个同名目录可见时才协调为成功。

本后端有意不注册快速 `Purge`；rclone core 必须枚举并删除每个已知 ID。

`Move` 和 `DirMove` 只允许在同一账号 UID 内使用。仅改名称或仅改父目录时只执行一次服务端操作；两者同时变化时，先使用一个 128 位随机临时名称，移动精确 ID，再进行 rename，失败时按相反顺序回滚。

已有目标 ID 绝不会被自动删除；禁止把目录移动到自身子树；目录移动涉及的全部 dircache 条目都会失效。

同一账号 UID 的所有 remote 实例共享写锁，并以父目录 ID 加编码后的服务端名称作为锁键，因此不同本地 root 别名仍会落到同一把锁。获得锁后，`Put`、`Update`、`Remove`、`Rmdir`、`Move` 和 `DirMove` 都会从逻辑 root 重新遍历父路径，在修改服务端状态前拒绝过期缓存 ID。

Web API 不提供原子的“仅空目录删除”，也不提供原子 move+rename。这些检查可以降低风险，但无法消除另一个客户端造成的竞态；破坏性自动化应使用隔离根目录。

## rclone 能力说明

- `Hashes()` 返回 MD5，`SlowHash=false`。空、畸形或并非 MD5 的 ETag 会让 `Object.Hash(MD5)` 返回明确协议错误，绝不以空字符串加 nil error 退化为尺寸判等。
- `PartialUploads=false`：服务端对象只有在完成接口和严格终态协调后才作为可见成品返回；rclone core 不再自动创建 `.partial` 临时名。
- `Precision()` 返回 `fs.ModTimeNotSupported`；服务端 `UpdateAt` 仍可在列表中显示，但 `SetModTime` 返回 `fs.ErrorCantSetModTime`。
- 支持空目录和零字节文件。由于没有经过验证的 abort API，传输失败后服务端可能残留部分上传；已知时，错误会报告其精确 file/upload ID。
- 不注册 `Copy`。rclone 会按需下载或调用 `Put`；`Put` 在传输正文前仍会尝试 MD5 秒传。
- 不注册 `Purge` 和 `ListR`。有意使用 core 递归，以保留逐 ID 安全检查和完整列表一致性校验。
- 隔离真实测试已确认错误大小写路径不会匹配现有对象，因此当前设置 `CaseInsensitive=false`；稳定版前仍需在专用账号运行完整 `rclone test info`，确认 Unicode、大小写折叠和规范化边界。

如果账号允许使用代理，可通过 rclone 常规 HTTP 代理配置处理防盗链场景。控制客户端与下载客户端始终分离，但同一账号使用多个出口 IP 可能触发 123 网盘风控。绝不能在登录 endpoint 前部署第三方凭据转发服务。

## 离线任务

可以通过标准后端命令和 RC `backend/command` endpoint 使用离线下载：

```console
rclone-123 backend offline-add 123:destination URL
rclone-123 backend offline-status 123: TASK_ID...
rclone-123 backend offline-delete 123: TASK_ID...
```

`offline-add` 只解析一个 URL，并保存到构造该后端时使用的 remote 路径。状态输出使用稳定字段：任务 ID、名称、原始状态、规范化状态、大小、已下载字节、进度、速度和上传名称。

原始状态 0/1/2/3 分别规范化为 `downloading`/`failed`/`complete`/`retrying`；其他整数原样保留并标记为 `unknown`。ID 必须是互不重复的正整数。只有完整分页查询证明全部指定 ID 已不存在时，才会报告删除成功。
