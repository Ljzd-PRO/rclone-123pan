# 123Pan backend

The remote type is `123pan`, with flags prefixed by `--pan123-`.
Only personal-account username/password authentication is in scope.

The backend must connect directly to 123Pan. It does not use OpenList's public
token service, which belongs to the separate `123_open` driver.

The read-side implementation advertises MD5, preserves server update time for
display, and reports `fs.ModTimeNotSupported` because the web API cannot set it.
Every directory is read in pages of 100 using `file_id desc`; a result is
returned only after `Total`, unique IDs, names, and the termination marker all
agree. A failed consistency round is discarded in full and retried at most
three times.

Decoded names that collide, or any two entries with the same visible name and
different IDs, fail closed as a path-ambiguity error. No arbitrary object is
selected. Custom roots are resolved through ID-backed directory traversal and
the resolved root must be listable before initialization succeeds.

Downloads request fresh metadata, strictly unwrap optional Base64 parameters,
resolve either a 302 or JSON redirect without automatic redirect following,
and use a separate unauthenticated data-plane client. Range, seek, and suffix
requests are normalized through rclone and the returned status,
`Content-Range`, declared length, and actual stream length are checked. A final
CDN 403 refreshes the signed URL once; a partially read body is never resumed
silently.

Uploads first request MD5 from the source. A valid supplied MD5 and known size
allow a rapid-upload request without reading the body. Otherwise the source is
read once: inputs up to `hash_memory_limit` (10 MiB by default) are kept in
memory and larger or unknown-size inputs are securely spooled under
`--temp-dir`, then rewound with accounting restored. Declared size, actual size,
and MD5 must agree. `Reuse=true` remains only a candidate success until a fresh
listing proves ID, name, parent, size, MD5, and object type; a rapid hit reads
zero body bytes.

A rapid miss selects one of two explicitly validated modes. Three complete
temporary credentials use AWS SDK v2 against the supplied path-style endpoint;
no credentials use 123Pan presigned URLs. Partial credentials are rejected as
malformed. Presigned uploads use fixed 16 MiB parts, batches of ten URLs, and
three workers by default. A worker retains its exact part bytes across at most
three attempts; concurrent 403s coordinate one batch URL refresh. The producer
is back-pressured, so memory grows with concurrency rather than file size.
Zero-byte files still issue an explicit zero-length PUT.

Neither complete endpoint is blindly retried after an ambiguous response. The
backend instead searches for the exact file ID and proves name, parent, size,
and MD5. It reports the upload/file ID if that postcondition cannot be proven.

Replacing an existing file is serialized per target path and never overwrites
the old object in place. The backend uploads and verifies a 128-bit-random
staging name, renames the old ID to an equally unique backup, promotes the
staging ID, verifies the final object, then trashes only the recorded backup
ID. Lost responses are coordinated by observing the exact ID's current name.
Failures run the inverse operations; if rollback is incomplete, the error
contains only the exact staging and backup IDs required for manual recovery.

Deletion always means moving one freshly verified ID to the recycle bin.
`Rmdir` refuses the logical root and ID 0, requires two consecutive complete
empty listings, then revalidates directory ID, parent, and name. `Mkdir`
coordinates a lost response only when exactly one matching directory is
visible. The backend deliberately does not register fast `Purge`; rclone core
must enumerate and remove each known ID.

`Move` and `DirMove` are available only within the same account UID. A pure
rename or parent change uses one server operation. A combined change uses a
128-bit temporary name, moves the exact ID, then renames it, reversing those
steps on failure. Existing target IDs are never deleted, moving a directory
into its own subtree is rejected, and all dircache entries touched by a
directory move are invalidated.

The web API does not provide atomic empty-directory deletion or atomic
move+rename. These checks reduce risk but cannot eliminate races with a second
client; use isolated roots for destructive automation.
