# 真实账号测试记录

## 2026-08-15 官方 Web 协议取证

在用户授权的账号根中创建了一个 128 位随机名称的全新 anchor。两个 1 KiB 哨兵位于 anchor 内、活动 work 目录外；协议测试文件位于全新 work 目录。没有读取、移动、修改或删除任何既有对象。

官方 Web 取证阶段上传了两个 1 KiB 小文件和两个内容不同的 16 MiB+1 文件，总 payload 小于 34 MiB，文件与目录数量均远低于硬预算。四个对象都形成可见文件；随后由修复后的后端继续执行 1 KiB 普通上传与秒传闭环。

脱敏抓线确认：

- 页面来源为 `https://yun.123pan.cn/`，控制 API 为 `https://api.123278.com/b/api`；
- 单片线型为 `upload_request → s3_upload_object/auth → PUT → upload_complete/v2`；
- 16 MiB+1 多片线型为 `upload_request → s3_list_upload_parts → 分片授权/PUT → upload_complete/v2`；
- 完成请求包含完整上传上下文，只调用一次；
- 没有调用 `s3_complete_multipart_upload`、旧式 `upload_complete` 或固定等待；
- 数据面 PUT 不携带控制 API Authorization。

原始 HAR、请求头值、Cookie、token、临时凭据、上传 key、预签 URL、文件名、MD5 和真实对象 ID 均未写入仓库。脱敏结构见 `protocol/current-web-2026-08-15.json`。

### 修复后端闭环

生产实现按上述证据移除了 S3 merge、旧 complete 和固定等待，切换到当前控制域名与页面来源，并收紧了请求/响应 DTO。随后在同一隔离 work 目录依次完成：

1. 全新随机 1 KiB 文件经后端上传；列表得到正 ID、1024 字节和正确 MD5；完整下载与本地源逐字节一致；
2. 两个 anchor 哨兵在上传前后保持相同 ID、大小和 MD5；
3. 该 1 KiB 对象按最新 parent/name/ID 复核后移入回收站，连续两次完整列表确认不可见；
4. 用相同内容和新名称测试秒传时，首次后端按原规则因 `Reuse=true, FileId=0` 失败关闭，work 中没有目标或 partial 残留；
5. 官方 Web 随后确认零 ID 秒传只执行 `upload_request → list → file/info`，数据 PUT 和完成调用均为零；
6. 后端据此只通过父目录内唯一的名称/大小/MD5 对象协调正 ID，复测成功；完整下载仍与源逐字节一致，哨兵不变。
7. 使用一个同样为 1024 字节但 MD5 不同的本地文件执行只读 `rclone check --checksum`，命令以 `md5 differ` 和非零状态正确报告差异，没有把同尺寸误判为相同。
8. 依次上传全新 0、1、16 MiB−1、16 MiB 和 16 MiB+1 文件，全部严格匹配最终 ID、父目录、名称、大小和 MD5；非零文件均完整下载并与源逐字节比较一致，零字节经真实秒传形成正确空对象。
9. 16 MiB+1 两片上传的预申请 ID 与最终可见 ID 不同；后端使用 `upload_complete/v2` 返回的完整 `file_info` 映射验证终态，没有错误地只轮询预申请 ID。
10. 现有 16 MiB+1 协议文件完整下载 MD5 与本地源一致；新建可打印文本文件的前缀 Range、offset 100 Seek 和末尾 suffix-range 均逐字节匹配；错误大小写路径查询返回未找到，支持当前 `CaseInsensitive=false` 初值。

本轮累计分配仍远低于 100 文件、50 目录、单文件 160 MiB+1 和 512 MiB payload 硬预算。48 MiB+1 并发、160 MiB+1 第二批 URL、更新、移动、bisync、VFS 和挂载测试尚未执行。

## 2026-08-14 隔离冒烟测试

本次测试使用用户明确授权的真实个人账号，但该账号不是专用空测试账号，也没有配置测试根外不可变 sentinel。因此只执行低风险冒烟测试，不能替代稳定版门禁。

测试遵守以下边界：

- 只创建两个随机命名的全新 `rclone-test-[a-z0-9]{12}` 目录；
- 不读取任何既有文件正文，不对既有对象执行写入、移动、重命名或删除；
- 本地准备 14 个临时文件，源数据总上界小于 19 MiB，最大单文件为 16 MiB+1；
- 不超过 4 个本地子目录，远低于 100 个文件、50 个目录、单文件 2 GiB 和总量 10 GiB 的授权上限；
- 所有写命令固定 `--retries 1 --low-level-retries 1`，避免对结果不明确的非幂等请求反复重放。

### 已确认通过

- 手机号密码登录和用户信息读取；
- 账号根与隔离目录的严格列表；
- 创建不存在的命令根目录；
- 空命令根目录的两次空列表确认、按精确 ID 移入回收站；
- 清理后同时按随机名称和记录 ID 复查，两个测试目录的匹配数均为零；
- 全程没有可见测试文件落入账号根或隔离目录。

### 上传测试结果

第一轮使用 10 个小型 fixture，合计 17,895,511 字节，最大文件 16,777,217 字节。测试暴露了缺失命令根创建、冲突模式和分片 URL 结束边界问题；批次在发现错误后停止，隔离目录最终可见条目为零。

修复上述问题后，使用互不相同的新随机内容逐个测试 64 KiB、96 KiB、128 KiB 和 160 KiB 文件：

1. 服务端曾返回 `Reuse=true`、上传 key 和正文件 ID，但文件 ID 在 60 秒内始终不可见；
2. 改为只在完整元数据可见时接受秒传，否则使用服务端提供的上传 key；
3. 数据面 PUT 可传完 96 KiB 和 128 KiB，完成接口也可返回成功，但对象仍不可见；
4. 当时尝试过没有官方 Web 证据支持的显式 S3 合并，单分片合并返回业务码 500，终态仍不可见；
5. 每次都由后端终态校验失败关闭，没有把控制接口的成功响应误报为上传成功。

这些结果现在已由 2026-08-15 官方 Web 抓线解释：旧后端使用了过期控制域名、错误的 `upload_request` 形状以及无证据的 merge+旧 complete 组合。该错误 profile 已从生产实现和 mock 预言机中删除，新的 1 KiB 普通上传与秒传低层闭环已经通过；更高层测试仍须按门禁逐级推进。

### 清理与残留风险

两轮随机测试目录在清理前的递归可见条目均为零。目录删除命令返回成功，随后从账号根按名称和记录 ID 查询，匹配数均为零。凭据只存在于受控进程环境，测试结束前已经取消环境变量并退出进程；仓库和测试文档不保存账号、密码或 token。

服务端对失败的上传请求分配过正文件 ID，并可能保留不可见的临时 S3 分片。个人盘接口没有经过验证的 abort API，本项目不会猜测端点或按相似名称删除未知对象。因此只能证明“没有可见文件或目录残留”，不能证明服务端内部临时分片已经回收。

### 后续门禁

本阶段已完成以下门禁；后续测试继续沿用同一要求：

1. 按已确认的当前 Web 单片和多片线型重建生产上传状态机；
2. 重写状态化 mock，明确拒绝无证据的 merge+旧 complete 顺序；
3. 使用专用空账号、非零固定测试根和两个根外 sentinel；
4. 先用一个全新 1 KiB 文件验证上传、列表、下载与 MD5 完整闭环，再逐步扩大到零字节和 16 MiB+1；
5. 任何控制接口成功都必须以可见 ID、名称、父目录、大小和 MD5 的终态校验为准，不得降低一致性标准。
